# Разработка сервиса классификации электрокардиографических сигналов с использованием методов машинного обучения

Бобылев Денис

## Ожидаемый результат
FastAPI-сервис, принимающий на вход данные ЭКГ в выбранном формате, и возвращающий диагноз. 
Пользовательский интерфейс реализован через streamlit или html + css, обработка ЭКГ выполняется с помощью обученной модели.

## План выполнения работы
### Чекпоинт 1. Старт и планирование
- Согласование темы, целей, задач и ожидаемых результатов с куратором проекта;
- Постановка задачи поиска открытых источников ЭКГ-данных (обсуждение критериев поиска, уточнение требуемого объёма входных данных);
- Составление годового плана работы, предварительное обсуждение возможного распределения ролей участников команды;
- Создание командного чата и GitHub-репозитория. Оформление сопроводительного документа с темой, составом команды, куратором и планом проекта.

### Чекпоинт 2. EDA
- Выбор и загрузка открытых датасетов ЭКГ, изучение структуры записей и разметка классов;
- Анализ качества данных, распределения классов, наличия пропусков и дубликатов и особенностей формата записи; 
- Поиск необходимого инструментария для чтения и обработки данных;
- Визуализация характерных примеров классов ЭКГ-данных, формулирование выводов об основных свойствах датасетов;
- Определение списка ключевых признаков (статистических, временных и частотных), выбор необходимых методов и инструментов для предварительной обработки исходных сигналов;
- Разделение данных на группы, содержащие одну патологию и несколько патологий для начального и последующих этапов обучения. 
- Подготовка обучающей, валидационной и тестовой выборки.

### Чекпоинт 3. Первые ML-модели
- Выбор основных метрик качества с учётом особенностей постановки задачи и распределения классов данных;
- Обучение и тестирование базовых ML-моделей: KNN, случайный лес (RF), градиентный бустинг (GBDT), сопоставление характеристик качества выполняемой классификации;
- Настройка параметров моделей и анализ полученных ошибок.
- Оценка влияния значений гиперпараметров моделей, методов предобработки и состава признаков на целевые метрики качества выдаваемых прогнозов;
- Сопоставление итоговых результатов работы моделей на валидационных данных, выбор наиболее эффективной ML-модели для реализации сервиса.

### Чекпоинт 4. ML-сервис
- Выбор поддерживаемых форматов загружаемых пользователем ЭКГ-данных и формата ответа сервиса;
- Разработка сервиса на FastAPI для загрузки и проверки входных данных;
- Реализация пользовательского интерфейса на Streamlit;
- Программная реализация предварительной обработки данных (фильтрация, нормализация, выделение фрагментов данных), извлечения признаков и классификации обученной ML-моделью;
- Разработка функционала выдачи результатов классификации в пользовательской форме и обработки некорректных запросов;
- Проверка работоспособности ML-сервиса и подготовка инструкции по запуску с примерами запросов.
- Формирование стандартизированного ответа API. 
- Тестирование и подготовка документации.

### Промежуточная защита
- Подготовка презентационных материалов, включающих информацию о поставленных задачах проекта, характеристиках используемых исходных данных, результатах обучения, тестирования и сопоставления характеристик ML-моделей;
- Демонстрация работы ML-сервиса автоматической классификации ЭКГ-данных;
- Составление отчёта о выявленных ограничениях, описание планируемых работ по дальнейшему совершенствованию модели классификации и функционала сервиса.

### Чекпоинт 5. Улучшение ML-модели
- Поиск дополнительных информативных признаков в данных исходных датасетов (характеристики формы ЭКГ и сердечного ритма);
- Исследование влияние различных методов фильтрации сигналов, способов нормализации и методов работы с дисбалансом классов;
- Подбор и настройка дополнительных гиперпараметров, анализ чувствительности характеристик работы ML-моделей; 
- Анализ ошибок классификации и качество работы на разных классах;
- Формирование и тестирование ансамблей ML-моделей для работы с разными классами при наличии ярко выраженных преимуществ различных архитектур на отдельных участках данных;
- Выбор лучших решений, обновление ML-модели в сервисе.

### Чекпоинт 6. Нейронные сети
- Подготовка входных ЭКГ-данных для обучения нейронных сетей: временные последовательности и спектрограммы;
- Обучение и тестирование различных архитектур нейросетевых моделей;
- Настройка параметров обучения, применение методик снижения влияния переобучения (ограничение сложности, регуляризация, промежуточные проверки метрик модели в ходе обучения, случайное отключение слоёв нейросети, включение дополнительных данных в датасет, аугментация данных);
- Сопоставление нейросетевых и классических подходов по качеству классификации и вычислительным затратам;
- Выбор итогового решения на основе результатов валидационных тестов для последующей интеграции в сервис.

### Чекпоинт 7. Финальные доработки
- Настройка MLflow для учёта статистики прогнозов, параметров, метрик работы моделей;
- Проверка воспроизводимости результатов на этапах подготовки данных, обучения и тестирования моделей; 
- Итоговое обучение выбранной модели классификации;
- Оценка итоговой модели на отложенной тестовой выборке, анализ ошибок и устойчивости;
- Интеграция итоговой модели в сервис, проверка полного сценария работы сервиса: от загрузки ЭКГ-данных до получения результатов классификации;
- Итоговое оформление инструкций по работе с сервисом и репозитория проекта.

### Итоговая защита
- Подготовка итогового отчёта и презентационных материалов по результатам реализации годового проекта;
- Демонстрация работы готового сервиса;
- Представление результатов исследования.
- Формулирование основных выводов по результатам проделанной работы, описание возможного направления дальнейшего развития проекта.
